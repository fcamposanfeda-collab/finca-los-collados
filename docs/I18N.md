# Internacionalización (ES / EN / FR)

El sitio usa **i18n nativo de Astro** (`prefixDefaultLocale: false`). El español queda en las URLs actuales. Inglés y francés van con prefijo.

| Idioma | Prefijo | `html lang` | Booking.com `lang=` |
| --- | --- | --- | --- |
| Español (por defecto) | ninguno | `es` | `es` |
| English (GB) | `/en/` | `en-GB` | `en-gb` |
| Français | `/fr/` | `fr` | `fr` |

No hay redirección automática por navegador, IP ni `localStorage`. El selector guarda preferencia al pulsar ES · EN · FR, pero no cambia la URL por su cuenta.

## Arquitectura

- Diccionarios JSON: `src/i18n/messages/{locale}/{namespace}.json`
- Tabla de slugs: `src/i18n/routes.ts` (`pageSlugs`)
- Catch-all EN/FR: `src/pages/[locale]/[...page].astro` hace `Astro.rewrite()` a la plantilla española. El idioma de la URL original se conserva con `src/i18n/render-context.ts` y `src/middleware.ts` (un `rewrite` pierde `Astro.url`).
- Enlaces internos: `useI18n(Astro).href('alojamiento')` → `/alojamiento`, `/en/accommodation`, `/fr/hebergement`
- Selector: `src/components/i18n/LanguageSwitcher.astro` (cabecera y pie)

Para añadir un idioma (p. ej. alemán):

1. Entrada en `src/i18n/config.ts` (`locales` + `localeMeta`).
2. Slugs en `pageSlugs` de `src/i18n/routes.ts`.
3. Copiar `src/i18n/messages/es/` a `src/i18n/messages/de/` y traducir.
4. Añadir el locale en `astro.config.mjs`.

No hace falta tocar componentes ni páginas si las claves JSON coinciden.

## Formularios, Booking y contacto

- **Motivo**: `value` estable (`general`, `alojamiento`, `evento`…). La etiqueta visible se traduce.
- **Correo a la finca**: etiquetas siempre en español + campo `idioma` (`ES` / `EN` / `FR`). El asunto interno usa la etiqueta española del motivo.
- **mailto** público (cabecera/pie/nota): asunto según el idioma de la página.
- **WhatsApp**: mensaje según el idioma de la página.
- **Booking.com**: URL neutra (sin `.es.html`) + `lang=es|en-gb|fr`.
- **Web3Forms**: la nota de configuración solo se muestra en desarrollo si falta la clave. En producción no aparece.
- Fechas: `input type="date"` nativo con `lang` del idioma. Sin date picker propio.
- Sin banner de cookies extra.

## SEO

- `hreflang` en cada página (es, en-GB, fr, x-default → español).
- Canonical = URL de esa lengua.
- `og:locale` + `og:locale:alternate`.
- JSON-LD `LodgingBusiness` con `inLanguage` y `url` de la página.
- Sitemap con pares hreflang; se excluyen las 404.
- GitHub Pages solo sirve el `404.html` raíz: esa página redirige a `/en/404` o `/fr/404` si la URL empieza por `/en/` o `/fr/`. No es redirección por idioma del navegador.

## Comprobar traducciones

```bash
npm run check:i18n
```

Comprueba que EN y FR tienen las mismas claves que ES y que no hay cadenas vacías (salvo `es.legal.disclaimer`, vacío a propósito).
